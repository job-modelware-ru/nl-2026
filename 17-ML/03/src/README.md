# Примеры к презентации 3: парадигмы и среда выполнения

База примеров — **OCaml 5.4** и **F# 9**. Это фиксированные версии учебного материала. Для OCaml не нужны сторонние библиотеки. Каждый файл запускается независимо от остальных.

Код между маркерами `BEGIN SLIDE` и `END SLIDE` совпадает с кодом соответствующего слайда. Комментарии и дополнительные вызовы помогают запустить пример самостоятельно. Файл для слайда 6 содержит дополнительную демонстрацию F# к сравнительному слайду.

## Запуск OCaml

Откройте терминал в папке с примерами. Для последовательного примера:

```sh
ocaml slide_07_functional.ml
```

Сборка и запуск примера с доменами:

```sh
mkdir -p _build
ocamlopt -o _build/domains slide_04_domains.ml
./_build/domains
```

Сравнение двух способов компиляции одного исходника:

```sh
ocamlc -o _build/backend.byte slide_15_backend.ml
ocamlrun _build/backend.byte
ocamlopt -o _build/backend.native slide_15_backend.ml
./_build/backend.native
```

Первый запуск выводит `bytecode`, второй — `native`. При компиляции OCaml также создаёт служебные `.cmi`, `.cmo`, `.cmx` и `.o` рядом с исходником.

Для запуска всех OCaml-примеров по порядку в macOS/Linux:

```sh
mkdir -p _build
for file in slide_*.ml; do
  name=${file%.ml}
  printf '\n%s\n' "$file"
  ocamlopt -o "_build/$name" "$file" && "_build/$name" || break
done
```

## Запуск F#

Нужен .NET SDK с F# Interactive, поддерживающим F# 9:

```sh
dotnet fsi --langversion:9.0 slide_06_async.fsx
dotnet fsi --langversion:9.0 slide_09_interfaces.fsx
```

## Важные ограничения

- Домен соответствует потоку ОС. Короткая сумма показывает механизм, а не доказывает выигрыш производительности.
- `Atomic.incr` выполняет увеличение атомарно. Раздельные `Atomic.get` и `Atomic.set` не дают той же гарантии для всей последовательности.
- `Async.Sleep` позволяет перекрыть ожидания; пример F# не измеряет ускорение вычислений на процессоре.
- Класс OCaml и интерфейс F# представляют разные механизмы. Структурные объектные типы OCaml не требуют общего предка; F#-пример явно реализует именованный интерфейс.
- GADT не позволяет составить `Add (Int 1, Bool true)`. Ошибочный фрагмент оставлен только комментарием.
- `Lazy.force` выполняется последовательно. Для общего ленивого значения и нескольких задач нужна синхронизация.
- В эффекте `Ask` продолжение возобновляется ровно один раз. Наличие обработчиков всех эффектов не проверяется статически. Синтаксис `effect Ask, k` требует OCaml 5.3 или новее и поддерживается выбранной 5.4.
- Пример ресурсов создаёт новый временный файл и удаляет его. Закрытие каналов предусмотрено при обычном возврате и исключении внутри callback; аварийное завершение процесса — отдельный случай.

## Проверка

Все **12 файлов OCaml** независимо скомпилированы и выполнены компилятором **OCaml 5.4.0** в двух режимах: байткод и машинный код. **24 из 24 запусков** завершились успешно, вывод совпал с указанным.

Для проверки использовалась временная сборка компилятора; она не является частью набора примеров. Файлы F# сверены чтением с официальной документацией; .NET SDK в рабочем окружении не обнаружен, поэтому запуск F# не выполнялся.
