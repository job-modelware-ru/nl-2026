# Примеры ко второй презентации Odin

Все 15 файлов `.odin` лежат непосредственно в `src`. Их имена уникальны. Подпапок в `src` нет.

Официальный релиз: **dev-2026-11a** от 3 ноября 2026 года. Компилятор из macOS arm64 архива этого релиза сообщает версию **dev-2026-11-nightly:9a69916**. Технические источники проверены 9 ноября 2026 года. После переноса файлов все примеры повторно скомпилированы и запущены **16 ноября 2026 года**.

## Запуск

Установите соответствующий официальный компилятор Odin и добавьте его в PATH. Для линковки на macOS нужен Apple clang и SDK. `run_examples.py` использует только стандартную библиотеку Python 3.

Команды из корня проекта:

```sh
odin version
python3 src/run_examples.py all
python3 src/run_examples.py 01_packages
python3 src/run_examples.py 02_platform
python3 src/run_examples.py 03_generics
python3 src/run_examples.py 04_stack
python3 src/run_examples.py 05_context
python3 src/run_examples.py 06_arena
python3 src/run_examples.py 07_temp
python3 src/run_examples.py 08_tracking
python3 src/run_examples.py 09_soa
python3 src/run_examples.py 10_sets
```

`01_packages` и другие аргументы здесь являются идентификаторами примеров, а не именами подпапок. Для отдельного запуска достаточно выбрать один идентификатор. Аргумент `all` последовательно запускает все десять примеров и печатает их идентификаторы перед результатами.

Если компилятор находится вне PATH, задайте его путь:

```sh
python3 src/run_examples.py all --odin /path/to/odin
```

Путь также можно передать через переменную окружения `ODIN`. Скрипт работает независимо от текущего рабочего каталога, если обратиться к нему по правильному пути. Флаг `-debug` включён в команды запуска, поэтому платформенный пример печатает `debug build`.

Проверка платформенного примера для другой целевой платформы без запуска:

```sh
python3 src/run_examples.py 02_platform --check-target linux_amd64
python3 src/run_examples.py 02_platform --check-target windows_amd64
```

## Плоское хранение и структура пакета

В Odin пакет соответствует каталогу. Поэтому общий `src` с независимыми программами и объявлениями `package main` и `package calc` предназначен для хранения листингов, а не для сборки целиком командой `odin run src`.

Для примера `01_packages` скрипт копирует три файла во временный каталог операционной системы и создаёт следующую структуру. Имена файлов остаются теми же:

```text
<временный каталог>/project/
    01_packages_main.odin
    calc/
        01_calc_square.odin
        01_calc_internal.odin
```

Таким образом, импорт `import calc "calc"` остаётся рабочим, а две реализации `package calc` принадлежат одному пакету. Папка `calc` существует только во временной копии для компиляции.

Для `02_platform` во временный каталог копируются четыре файла `02_platform_*.odin`. Суффиксы `_darwin`, `_linux` и `_windows` сохраняются, и компилятор выбирает подходящую реализацию. Для примеров `03_generics`–`10_sets` скрипт запускает один исходник с флагом `-file`.

Скрипт передаёт `-out` с путём во временном каталоге. Исходники, промежуточная структура пакетов и исполняемые файлы из временной копии удаляются после завершения запуска. В `src` не создаются ни бинарные файлы, ни служебные подпапки.

При необходимости одиночный пример можно запустить напрямую, указав отдельный путь для бинарника:

```sh
odin run src/03_generics.odin -file -debug -out:/tmp/odin-generics
```

Эта прямая команда оставляет бинарник `/tmp/odin-generics`; автоматическую очистку обеспечивает запуск через `run_examples.py`.

## Назначение и слайды

Актуальная презентация содержит 24 слайда и рассчитана на 15–20 минут. Все примеры показаны на слайдах. Для выступления достаточно одного короткого запуска, остальные результаты приведены рядом с кодом.

| Пример | Исходники в src | Что показывает | Слайды |
|---|---|---|---|
| `01_packages` | `01_packages_main.odin`, `01_calc_square.odin`, `01_calc_internal.odin` | Несколько файлов в пакете, импорт с псевдонимом, закрытая процедура | 2–4 |
| `02_platform` | `02_platform_main.odin`, `02_platform_darwin.odin`, `02_platform_linux.odin`, `02_platform_windows.odin` | Выбор файлов по ОС и ветви `when ODIN_DEBUG` | 5–6 |
| `03_generics` | `03_generics.odin` | Вывод `$T`, явный параметр типа, ограничение `where` | 7–8 |
| `04_stack` | `04_stack.odin` | `Stack(T, N)`, процедуры `push`/`pop`, две специализации | 9–11 |
| `05_context` | `05_context.odin` | Область действия `context` и явный параметр аллокатора | 13–14 |
| `06_arena` | `06_arena.odin` | Арена поверх локального буфера и наследование аллокатора | 15 |

## Важные условия

- `02_platform` содержит реализации для macOS (`darwin`), Linux и Windows. Компилятор выбирает файл по целевой платформе. С флагом `-debug` выполняется ветка `ODIN_DEBUG`; без него программа печатает `normal build`.
- В `06_arena` локальный буфер принадлежит `main`. Выделенные из арены срезы используются до `arena_free_all` и до выхода из `main`. Сброс арены не обнуляет все старые указатели автоматически. Арена фиксированного размера ограничена 4096 байтами и не освобождает отдельные объекты.
- В `07_temp` после `free_all(context.temp_allocator)` программа использует только независимую копию `owned`. Читать `scratch` после сброса нельзя.
- `08_tracking` намеренно освобождает все данные. Чтобы показать утечку на занятии, можно временно закомментировать `delete(values, allocator)` и завершающий `assert`: счётчик останется ненулевым. Возвратите строки после демонстрации. Разрушение tracking allocator само по себе не заменяет освобождение пользовательских объектов.
- В `09_soa` показано равенство результатов. Измерений времени нет, поэтому пример не доказывает ускорение.
